# Phase 1 Implementation Task: Model Storage Foundation

## Context
You are implementing Phase 1 of the Model Management System for Vantage Forecaster. This is the foundational infrastructure for storing and managing trained forecasting models.

## Working Directory
C:\Source_Codes\Vantage-Forecaster

## Objective
Create the model storage infrastructure including SQLite registry, binary file operations, TypeScript types, and basic CLI commands.

## Tasks

### 1. Create src/types/models.ts
Define TypeScript interfaces for:
- `SavedModel` - Complete model structure with metadata, metrics, featureConfig, modelData
- `ModelMetadata` - Model identification and training info
- `ModelMetrics` - Performance metrics (MAPE, RMSE, MAE, R2, bias, peak/offpeak MAPE)
- `ModelFeatureConfig` - Feature list, normalization params, categorical mappings
- `ModelRegistry` - Database row structure
- Entity types: 'regional' | 'zonal' | 'wind' | 'solar' | 'hydro' | 'biomass' | 'geothermal' | 'battery'
- Model types for demand: 'xgboost' | 'hybrid' | 'regression'
- Model types for CFAC: '4tier' | 'mrec' | 'physics' | 'hybrid'

### 2. Create src/services/modelStore.ts
Implement:
- **Database initialization**: Create `models/registry.db` with schema from MODEL_MANAGEMENT_PLAN.md
- **Model registry operations**:
  - `saveModel(model: SavedModel): Promise<string>` - Save model to registry + binary file
  - `getActiveModel(entityType: string, entityCode: string): Promise<SavedModel | null>`
  - `listModels(filters?: { entityType?, entityCode?, isActive? }): Promise<ModelRegistry[]>`
  - `getModelById(id: string): Promise<SavedModel | null>`
  - `activateModel(id: string): Promise<void>` - Ensure only one active per entity
  - `deleteModel(id: string): Promise<void>` - Remove from registry + delete file
  - `archiveModel(id: string): Promise<void>` - Mark as archived
- **Binary file operations**:
  - Write binary files to `models/{demand|cfac}/{type}/{entity}/v{version}_{timestamp}_{modelType}.vfm`
  - Use MessagePack for serialization
  - Calculate SHA256 checksum for integrity
  - Read binary files and deserialize
- **Directory structure creation**: Create `models/` folder structure on first run

### 3. Create src/services/modelSerializer.ts
Implement:
- `serialize(model: SavedModel): Buffer` - Convert SavedModel to MessagePack binary
- `deserialize(buffer: Buffer): SavedModel` - Convert binary back to SavedModel
- Include header validation (magic bytes "VFM1")
- Checksum validation

### 4. Create src/commands/models.ts
Implement CLI commands:
- `models init` - Initialize model store (create directories + database)
- `models list [--entity-type <type>] [--entity-code <code>] [--active-only]` - List models with filtering
- `models info <id>` - Show detailed model information including metrics

### 5. Update src/index.ts
Add the new `models` command to the CLI using Commander.js

## Database Schema Reference
Use the schema from Documents/planning/MODEL_MANAGEMENT_PLAN.md lines 102-176.

Key tables:
- `models` - Main registry with metadata, metrics, file paths
- `model_groups` - Group model definitions (e.g., 'all_solar')

## File Format
.vfm files (Vantage Forecast Model):
- Binary MessagePack format
- Header with magic bytes, version, checksum
- Metadata section (JSON-like structure)
- Model data section (serialized model-specific data)
